# Tables

This directory contains the table creation scripts for the Oracle Banking Database project.

The schema currently consists of **26 tables**, organized into logical business and technical domains to provide a clear and maintainable deployment structure.

## Directory Contents

| Script | Purpose | Tables |
|---|---|---:|
| `01_Create_Reference_Tables.sql` | Creates reference and lookup tables | 10 |
| `02_Create_Customer_Tables.sql` | Creates customer and company domain tables | 6 |
| `03_Create_Account_And_Card_Tables.sql` | Creates branch, account, beneficiary, card, and exchange-rate tables | 5 |
| `04_Create_Transaction_And_Log_Tables.sql` | Creates transaction, history, audit, and error logging tables | 5 |

**Total: 26 tables**

## 01 - Reference Tables

`01_Create_Reference_Tables.sql` creates the reference and lookup structures used throughout the banking schema.

Tables:

- `COUNTRIES`
- `CITIES`
- `DISTRICTS`
- `SECTORS`
- `CURRENCIES`
- `ACCOUNT_TYPES`
- `CARD_TYPES`
- `CONTACT_TYPES`
- `TRANSACTION_CHANNELS`
- `TRANSACTION_TYPES`

These tables provide standardized reference data for geographic, financial, customer-contact, account, card, and transaction-related operations.

## 02 - Customer Domain Tables

`02_Create_Customer_Tables.sql` creates the core customer structures.

Tables:

- `COMPANIES`
- `CUSTOMERS`
- `INDIVIDUAL_CUSTOMERS`
- `CORPORATE_CUSTOMERS`
- `CUSTOMER_ADDRESSES`
- `CUSTOMER_CONTACTS`

The design separates common customer information from individual and corporate customer-specific attributes.

Customer address and contact information is maintained in dedicated tables to support multiple records per customer.

## 03 - Account and Card Domain Tables

`03_Create_Account_And_Card_Tables.sql` creates the structures used for branch, account, beneficiary, card, and exchange-rate management.

Tables:

- `BRANCHES`
- `ACCOUNTS`
- `BENEFICIARIES`
- `CARDS`
- `EXCHANGE_RATES`

These tables form the core banking relationship between customers, branches, accounts, registered beneficiaries, issued cards, and currency exchange information.

## 04 - Transaction and Logging Tables

`04_Create_Transaction_And_Log_Tables.sql` creates the transactional and technical logging structures.

Tables:

- `TRANSACTIONS`
- `TRANSACTION_STATUS_HISTORY`
- `AUDIT_LOGS`
- `ERROR_LOGS`
- `DDL_AUDIT_LOGS`

`TRANSACTIONS` stores banking transaction records, while `TRANSACTION_STATUS_HISTORY` provides status-change history.

The remaining tables provide application auditing, diagnostic error logging, and schema-level DDL auditing.

## Design Approach

The table scripts define the physical table structures, including:

- Column names
- Oracle data types
- Column lengths and numeric precision
- `NULL` / `NOT NULL` definitions
- Column default values
- Identity columns

Identity columns use `GENERATED BY DEFAULT AS IDENTITY`.

For clean deployments, identity definitions start from `1`. Runtime identity sequence positions from the populated development database are intentionally not reproduced in these scripts.

Primary keys, unique constraints, foreign keys, and named check constraints are maintained separately under the `03_Constraints` module.

Supporting indexes are maintained separately under the `04_Indexes` module.

This separation keeps table creation, relational integrity, and indexing responsibilities clearly organized.

## Deployment Order

Run the scripts in the following order:

1. `01_Create_Reference_Tables.sql`
2. `02_Create_Customer_Tables.sql`
3. `03_Create_Account_And_Card_Tables.sql`
4. `04_Create_Transaction_And_Log_Tables.sql`

The scripts are intended for an empty target schema or a controlled database rebuild.

They should not be executed directly against an existing populated schema containing objects with the same names.

## Validation

The table definitions were validated against the current `BANKING_DB` schema metadata.

Validation covered:

- Table existence
- Object validity
- Column names and order
- Data types
- Character lengths
- Numeric precision and scale
- Nullability
- Default values
- Identity-column configuration
- Expected column counts

All **26 table definitions** included in this module were accounted for during the metadata review.
