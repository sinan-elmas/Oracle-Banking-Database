# Sequences

This directory contains the explicitly managed application sequence definitions for the Oracle Banking Database project.

Oracle-managed sequences created internally for identity columns are intentionally excluded from this module.

## Directory Contents

| Script | Purpose | Sequences |
|---|---|---:|
| `01_Create_Sequences.sql` | Creates explicitly managed application sequences | 2 |

**Total explicitly managed sequences: 2**

## Application Sequences

`01_Create_Sequences.sql` creates the following sequences:

- `CARD_SEQ`
- `SEQ_CUSTOMER_NO`

Both sequences use the following deployment configuration:

```sql
START WITH 1
INCREMENT BY 1
MINVALUE 1
MAXVALUE 9999999999999999999999999999
CACHE 100
NOCYCLE
NOORDER
```

These sequences are explicitly defined and managed as part of the application schema.

## Runtime State vs Deployment Definition

Sequence runtime state changes as sequence values are consumed.

Metadata inspection of the populated development database showed the following runtime values:

| Sequence | Runtime `LAST_NUMBER` |
|---|---:|
| `CARD_SEQ` | 8113 |
| `SEQ_CUSTOMER_NO` | 10405 |

These values represent runtime state in the populated development database and are not structural schema definitions.

For this reason, both sequences use:

```sql
START WITH 1
```

in the deployment script.

This keeps the sequence definitions suitable for clean and repeatable schema deployment rather than reproducing transient runtime state.

## Oracle-Managed Identity Sequences

The current schema contains **24 additional Oracle-managed identity sequences**.

Their names follow Oracle's internal naming pattern:

```text
ISEQ$$_...
```

These sequences correspond to identity columns defined in the table layer, for example:

```sql
GENERATED BY DEFAULT AS IDENTITY
```

Oracle automatically creates and manages the required internal sequence when an identity column is created.

For this reason, Oracle-managed identity sequences are intentionally not included in `01_Create_Sequences.sql` and their generated object names are not reproduced in the deployment scripts.

## Deployment

Run the sequence script as part of a clean schema deployment:

```text
01_Create_Sequences.sql
```

The script creates only the explicitly managed application sequences.

Oracle-managed identity sequences are created automatically with their corresponding identity columns in the table layer.

## Design Principles

- Explicit application-managed objects are version controlled.
- Oracle-generated internal objects are not manually recreated.
- Runtime sequence state is not treated as a structural schema definition.
- Clean deployments use deterministic starting values.
- Identity sequence management remains with Oracle.
